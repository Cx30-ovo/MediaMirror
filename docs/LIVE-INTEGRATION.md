## 启动与配置

推荐 Node.js 22 或更新版本。本机已用 Node.js 24 验证。

项目根目录已经创建 `.env`，数据接口地址已填入。只需补全：

```dotenv
MODEL_BASE_URL=https://你的服务地址/v1
MODEL_NAME=你的模型名
MODEL_API_KEY=你的密钥
```

`MODEL_BASE_URL` 是服务前缀，不包含 `/chat/completions`。当前实现支持兼容 Chat Completions 的模型服务，不保证其他协议直接可用。例如 DeepSeek、Qwen 的实际服务地址和模型名以供应商账号文档为准。

如果服务支持 JSON 模式，可设置 `MODEL_JSON_MODE=true`。需要 `max_completion_tokens` 的服务设置 `MODEL_TOKEN_FIELD=max_completion_tokens`。没有设置服务商、模型名和密钥时，页面不会发起正式模型分析。

```powershell
npm run dev
```

默认打开 `http://127.0.0.1:5182/`，进入“数据与设置”。dev 和 preview 都固定使用 5182，端口占用时明确报错，不自动切换；同时只运行其中一个。显式指定其他端口时，以终端显示地址为准。如果构建后运行，使用 `npm run build` 和 `npm run preview`。不要双击 dist/index.html 或用普通静态服务器运行，因为连接服务随 Vite dev/preview 启动。生产部署仍需独立后端与调度服务。

若显示“连接服务返回 404”或“当前页面找不到融媒评馈分析服务”，先核对地址。当前本机的 5173 由另一个“内容情报编辑台”项目占用，它的接口不包含 `/api/integration/*`，不能用其地址调用本 Demo 的事件分析。应打开 5182，避免在旧页面中继续操作。工作台接口缺失与上游模型服务返回 HTTP 404 是两种错误，后者应检查模型服务前缀和配置。

`.env` 只由本地服务读取；前端只获得“是否配置”等状态，不获得密钥。该文件已忽略提交，不要使用 `VITE_` 前缀存放密钥。`.env.example` 为无密钥模板。修改配置后点击连接测试；如服务正在重启，稍后刷新页面即可。

## 建议的单次测试顺序

1. **重新读取各 10 条**：核对四平台数量、标题、正文、链接与互动字段。
2. **测试模型连接**：只发送一条很短的 JSON 回复请求，不发送新闻或评论；成功仅证明服务返回有效响应。
3. **测试事件归并**：发送这 40 篇中尚未归并作品的标题、发布时间及最多 2000 字正文节选。节选明确标记是否截断。不是同一个具体事件的作品不能仅因主题类似而合并；无法判断可暂不归组。
4. **测试单个事件分析**：选择一个事件，发送其实际关联作品及已收录评论；检查摘要、内容互补和原文证据。缺少评论时受众关注、疑问、建议、争议数组必须留空；没有竞品时竞品对比留空。
5. 在“跨平台事件分析”查看结果和作品依据，在“全域聆听 → 全域信息流”查看全部已读取作品，包括暂未归并的作品。

每条发现需要有效作品或评论 ID。服务端和前端会校验证据引用，但“ID 存在”不等于语义判断准确。模型分组仍可能误合并，须用小样本评估。

## 自动模式

默认 `MODEL_AUTO_ANALYZE=false`，先做单次测试。核对结果后设置为 `true` 并在工作台恢复自动观察。页面打开期间，每隔 1/5/15 分钟重新读取每平台最新 10 条，归并尚未归入事件的新作品，并分析材料发生变化的事件。首次自动分析也受调用上限限制。

当前默认不限制每小时模型请求次数：`MODEL_MAX_CALLS_PER_HOUR=0`。连接测试、归并、评论分类和事件分析仍串行执行，每次请求有90秒超时，并保留任务预算、分批处理及失败校验。需要本地限额时可将此项设置为正整数；它只按本地服务进程计数，不是正式计费系统。

输入指纹忽略仅观测时间的变化，保留作品正文、互动、评论与归属等变化，避免没有内容变化仍重复调用。因为本轮按最新 10 篇滚动取样，作品离开样本后，不再出现在当前事件分析中；历史事件归属保留在本地，不能把当前窗口当作全量事件档案。

关闭页面后不调度，无桌面通知、后台常驻任务或跨设备协作。服务端事件归属保存在已忽略提交的 `work/integration-events.json`。浏览器报告和跟进记录按真实数据源隔离保存，模型或提示词版本变化会隔离旧报告缓存。

## 字段映射

| 上游字段 | 系统字段与处理 |
| --- | --- |
| platform + external_work_id | `id = platform:external_work_id`，避免跨平台 ID 冲突；长 ID 必须为字符串 |
| id | `sourceId`，保留上游数据库 ID |
| title / content / url | 标题 / 正文及来源内容 / 原始 URL；只保留 HTTP(S) 链接 |
| account_name | 账号名；该接口当前明确为厦门广电自有账号 |
| owner（可选扩展） | `competitor` 才计为竞品；未来正式竞品接口需要另行确认来源 |
| like_count / comment_count / collect_count | 点赞 / 平台评论数 / 收藏；缺失保留 null，不补 0 |
| repost_count / share_count | 微博采用 repost_count，其他平台采用 share_count；不叠加可能重叠口径 |
| engagement_total | 原始互动合计，不计算跨平台质量评分 |
| published_at / last_seen_at | 保留上游 ISO 时间与时区，不用本地时间替代缺失的发布、观测时间 |
| tags | 上游话题字段，不代表模型识别出的报道角度 |

微信部分互动值由凡闻口径返回 0；这里保留上游值并显示口径说明，不能认为微信没有受众反馈。本轮没有使用互动增量或读取历史快照生成趋势。

## 评论与热点的后续接口

`.env` 中 `DATA_COMMENTS_PATH`、`DATA_HOTSPOTS_PATH` 默认留空。以下是本地适配器的**接入约定**，并不声称上游已有这些接口。确认真实结构后应按实际 API 编写映射和分页；不应直接假设字段一致。

评论返回：

```json
{"ok":true,"data":[{"id":"comment:100","workId":"weibo:5361839115600235","text":"具体疑问","author":"脱敏作者","at":"2026-11-06T10:00:00+08:00"},{"id":"comment:101","workId":"weibo:5361839115600235","parentId":"comment:100","replyTo":"脱敏作者","text":"子评论","author":"另一作者","at":"2026-11-06T10:10:00+08:00"}]}
```

当前接收全部已接入作品的评论。评论先显示“待分析/未分析”；不填入预设业务标签。父评论缺失、跨作品回复、循环、重复证据 ID 会报错，不静默修改原始关系。当前模型将评论归纳成报告发现，尚未逐条给原始评论打模型标签。

热点返回：

```json
{"ok":true,"data":[{"id":"hotspot:1","platform":"百度","title":"热点标题","observedAt":"2026-11-06T10:00:00+08:00","position":1,"url":"https://example.com/"}]}
```

只接受百度、今日头条，每平台最多保留 10 条；在信息流中作为未归入事件的背景展示。热点与事件的自动关联还未实现，不能凭关键词强行归入事件。可选接口必须同源，认证密钥从 `.env` 服务端读取。当前没有通用游标分页器；评论/热点接口确定后再实现。

## 验证与限制

`npm test` 使用本地夹具验证真实 HTTP 请求链、每平台 10 条限制、长 ID/null、父子评论、事件归属持久化、证据拒绝及密钥不返回。浏览器测试验证真实 40 篇作品展示、来源查看、筛选、错误提示与移动布局。

夹具模型用于验证程序流程，不代表真实模型分析效果。未配置用户密钥前，不能宣称真实模型连接或事件归并成功。本地原型 未实现登录、完整审计、队列、稳定持久化数据库或生产部署。

兼容请求字段参考官方接口文档：[Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。不同服务商支持范围需通过实际连接测试确认。

## 只采用真实数据与数据库方向

运行代码中已删除虚拟作品、评论、事件、演示分析器和本地自动生成的替代摘要，旧样本缓存不读取并会清理。断开接口时显示错误，不回退内置数据。后续数据库统一采用 MongoDB，详见 [存储规划](STORAGE.md)。测试目录里的隔离夹具仅验证协议，不进入应用数据。
