# 受众反馈自动分析

开启 `.env` 中 `MODEL_AUTO_ANALYZE=true` 且工作台自动观察开启后，页面加载与定时更新按以下顺序运行：读取真实数据 → 逐条分析新评论 → 归并事件 → 事件专项分析。保持页面打开才会定时运行，当前没有后台常驻调度。

## 输出

每条已收录评论、子评论由模型结合报道标题、正文节选和父评论判断：

- 主类别：信息疑问、纠错线索、内容建议、服务诉求、正向反馈、一般讨论、无法判断。
- 情绪：中性、积极、担忧、消极、无法判断。
- 指向主题和一条简短、可核对的判读说明。

“无法判断”表示模型已读但语境不足；“待分析/未分析”表示尚无有效模型结果。纠错线索并不代表报道确实出错，对事件的负面情绪不等于对媒体不满。结果需结合原文复核。没有评论原文的平台不能据评论统计数推断观点。

如果接口中的个别评论正文为空，保留空原文与父子ID，界面明确显示原文缺失；模型只能给出“无法判断/指向不明”，不能借用父评论编造该评论的观点。接口收录条数包含这些空正文记录，不能将它们当作有效观点样本。

## 输入、输出与费用边界

`POST /api/integration/classify-feedback` 只接受运行方式，不接收浏览器提供的评论语料。服务端从当前真实数据集中选取未分析评论，每批最多20条；目标评论每条最多2000字符，标题200字符，正文1200字符，最近4层祖先评论各600字符。材料总计不超过28000字符（并非token精算），截取处有标记。上下文不足时要求保守判断。长ID仅在服务端映射为 C01 等短编号。

每批一次模型请求，输出上限取 `MODEL_MAX_TOKENS` 与6000的较小值；主题最多40字符、说明最多100字符。结果必须覆盖本批全部评论，未知/重复编号、非法类别、缺漏或截断均整批拒绝，不把失败评论标为完成，也不自动重试付费请求。

每轮最多6批，所有评论分析、事件归并、报告、连接测试共用模型锁。`MODEL_MAX_CALLS_PER_HOUR=0` 表示不限每小时调用次数，为默认及当前设置；正整数可选开启本地限额。启用限额时，额度不足返回进度及可继续时间，下轮自动观察续跑。分批材料、单任务调用预算、超时、去重与任务锁继续生效。

## 保存与失效

分类结果保存在 `work/integration-feedback.json`，原始评论与上游数据不修改。每批有效结果原子保存，重启可恢复。缓存按数据来源、模型配置、提示版本、评论文本、父评论语境、报道标题和正文隔离；输入变化后重新分析。点赞、采集时间等变化不会重复支付文本分析费用。

暂用本地文件以适配单机Demo；后续依用户要求迁移到 MongoDB，可将评论原文与分析版本分集合保存，并补充服务端任务队列、多进程锁和持久化调用额度。

界面展示已分析/待分析数量，保留原文、父子评论以及“查看模型判读说明”。模型判断不代替编辑核实，统计仅覆盖已收录的评论样本，不代表全部受众。
