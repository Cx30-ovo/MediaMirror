# MediaMirror · 融媒评馈 v0.12

面向厦门广电编辑的真实数据评馈工作台。仅使用已接入的作品、互动与评论原文；没有内置虚拟作品、评论、事件或演示分析器。接口失败会提示错误，数据缺失显示空状态。

## 模型调用设置

当前已解除本地每小时调用次数限制：`.env` 中 `MODEL_MAX_CALLS_PER_HOUR=0`（0为不限次数）。分批处理、单任务输入输出预算、超时及模型任务串行执行继续生效。

## 事件分析更新

受众反馈现已接入逐条模型分析：自动阅读报道与父子评论，输出类别、情绪、具体主题及判读说明。新评论分批分析，结果在本机服务端保存，刷新和重启可恢复；内容变化重新分析，额度不足留待后续周期继续。参见 [受众反馈自动分析](docs/FEEDBACK-ANALYSIS.md)。

参考 BettaFish 的专项分工与交叉审阅，已实现“报道梳理 → 受众反馈 → 同事件媒体对照 → 证据审阅与简报”。缺数据自动跳过，单事件最多4次模型调用，无评论、竞品时为2次。页面展示步骤、覆盖与缺口，结论保留原文证据；这不等于事实核实。实现说明见 [BettaFish 适配](docs/BETTAFISH-ADAPTATION.md)。

## 快速启动

Windows 下双击项目根目录的 **启动Demo.cmd**，会自动检查 Node.js、补齐缺少的项目依赖，并在服务就绪后打开 `http://127.0.0.1:5182/`。如果 Demo 已在运行，只打开页面，不重复启动。首次运行需要 Node.js 22 或更新版本；缺少依赖时需要网络。

启动后保持运行窗口开启，在窗口内按 `Ctrl+C` 停止。本脚本保留现有 `.env`，仅在文件不存在时从模板创建；不会启动上游采集系统或主动发起模型测试。模型自动分析仍由 `.env` 配置决定。5182 被其他程序占用时会明确提示，不自动切换端口。

## 使用

1. 根目录 `.env` 已创建，填写 `MODEL_BASE_URL`、`MODEL_NAME`、`MODEL_API_KEY`。
2. `npm run dev` 启动，打开 [融媒评馈工作台](http://127.0.0.1:5182/)，进入“数据与设置”。默认固定 5182 端口，占用时明确报错，不自动换到其他端口。
3. 按“同步全部数据 → 测试模型连接 → 继续分批归并 → 单事件分析”顺序验证。
4. 单次测试确认后，可将 `MODEL_AUTO_ANALYZE=true`，启用页面打开期间的定时数据刷新与模型分析。

`npm run build` 构建；`npm run preview` 启动构建预览及本地连接服务。不能仅用普通静态文件服务器运行。推荐 Node.js 22 或更新版本；密钥仅由本地服务读取，不进入浏览器。

## 当前工作区

智能工作台、全域聆听、跨平台事件分析、受众反馈、矩阵观察、数据与设置。未归并作品在全域信息流查看，作品详情作为事件证据上下文，不建设独立作品资料库。

数据全量读取与模型批量处理分开：每轮归并最多40篇未归并作品，每批12篇，逐批保存进度；信息流每次显示100条，可继续加载。大事件超过40篇作品或100条评论会提示待分块，绝不静默截断。模型分析必须引用有效作品/评论 ID，事件归并也校验作品归属。没有评论原文不能从评论数量推断受众观点；没有竞品不能生成竞品比较。模型结果仍需结合原文判断。
